For documentation/writeup:
There are a number of C types which are deeply entangled with the compiler
because they're fundamental to the language.
They include:
Fun --used to implement functions
Ptr --used to implement pointers, entangled with the memory model.
The unsafe operation ptr[ix] is necessary for dealing with dynamically-sized
data; I say data and not types because the type system currently can't
capture types which don't have a statically bounded size.
Pair --the word-padding primitive; its runtime representation doesn't use the
default byte concatenation rule used by other constructors. It has zero-cost
construction and destruction. For that reason, tuples and vars are the only 
valid Core patterns.
Int --Int s len is a primitive, having a non-default representation.
All other datatypes are represented as the concatenation of field types; Int
is at the bottom of that hierarchy, unique in that it's nonempty but has no fields, indices or tag.
Int Signed is the only type compared using SGT and SLT rather than the
unsigned GT and LT.
Array is unique in that it has indices instead of fields; indices are
accessible via the infix ! operator.
